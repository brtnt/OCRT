\chapter{C LUT 예시 도구}
\label{chap:examples_readme}
\href{https://github.com/brtnt/OCRT/blob/main/docs/manual/examples/make_c_luts.py}{make\_c\_luts.py}는 \textbf{Python 표준 라이브러리로 C 실행 파일을 호출}한다. OCRT Python 물리 구현을 실행하는 도구가 아니다. 설치된 Python 3과 빌드된 OCRT C가 필요하다.

전체 옵션은 \texttt{python make\_\allowbreak{}c\_\allowbreak{}luts.\allowbreak{}py -\allowbreak{}-\allowbreak{}help}로 본다. 기본 격자는 테스트용으로 작다. 생산 정확도나 최적 격자를 뜻하지 않는다.

현재 해양 출력기의 배열 크기에 맞춰 simulation의 RAA 표본은 512개 이하로 제한한다. 이 제약은 방위각 간격과 관련되며 내부 Fourier 차수와는 다르다.

저장소 최상위에서 먼저 계획을 만든다.


\begin{ManualCode}
python3 docs/manual/examples/make_c_luts.py rayleigh \
  --ocrt-root code/OCRT_C --exe code/OCRT_C/build/ocrt \
  --outdir task/rayleigh_demo
\end{ManualCode}

생성된 \texttt{jobs.\allowbreak{}csv}와 \texttt{manifest.\allowbreak{}json}을 확인한 뒤 같은 명령에 \texttt{-\allowbreak{}-\allowbreak{}run}을 붙인다. \texttt{-\allowbreak{}-\allowbreak{}run} 없이도 버전 확인을 위해 \texttt{-\allowbreak{}-\allowbreak{}version}만 호출하지만 복사전달 계산은 수행하지 않는다. Windows는 \texttt{python3} 대신 \texttt{python}, 실행 파일은 \texttt{code/\allowbreak{}OCRT\_\allowbreak{}C/\allowbreak{}build/\allowbreak{}ocrt\_\allowbreak{}x86-\allowbreak{}64-\allowbreak{}v3.\allowbreak{}exe}를 사용한다.

각 사례는 CSV, 표준출력, 표준에러 로그를 저장한다. 행 수·주요 관측량의 유한수·해수 수렴 플래그를 검사하지만 수렴 정확도나 I/Q/U 대칭까지 자동 보장하지 않는다. 상향 전달비의 유효성은 사용자가 \texttt{T\_\allowbreak{}up\_\allowbreak{}rt\_\allowbreak{}valid}로 확인한다. 실패한 폴더를 그대로 재개하지 않으며 새 폴더를 사용한다. 외부에서 설정한 \texttt{OCRT\_\allowbreak{}*} 환경변수는 상속되고 manifest에 기록되므로, 진단·실험 변수가 켜진 셸인지 확인한다.

\texttt{jobs.\allowbreak{}csv}는 \textbf{이 도구의 계획표}이며 C의 \texttt{-\allowbreak{}-\allowbreak{}batch} 또는 \texttt{-\allowbreak{}-\allowbreak{}batch-\allowbreak{}full-\allowbreak{}grid} 입력 형식이 아니다. 전체 C 인자 배열은 \texttt{manifest.\allowbreak{}json}의 \texttt{argv}에 있다. 실행 파일 해시 외에도 사용 소스 커밋과 입력 자료 해시는 따로 보관한다.
