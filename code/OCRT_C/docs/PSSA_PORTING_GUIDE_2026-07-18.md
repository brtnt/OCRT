# OCRT PSSA 이식 가이드 (다른 수정본에 적용하기)
2026-07-18. 원본 기준: OCRT v1.1 릴리스. 이 문서는 v1.1에서 갈라져 나간 수정본(다른 세션 작업본)에 `--pssa`를 이식하는 절차를 기술한다.

## 0. 패키지 구성
1. `patch/pssa_patch_2026-07-18.diff`: v1.1 원본 대비 unified diff 전체. 대상 코드가 v1.1과 거의 같으면 `patch -p1` 또는 `git apply`로 직접 적용을 먼저 시도한다.
2. `src_full/`: 패치 완료 상태의 여섯 파일 전문(rt_pssa.h, rt_pssa.c, rt_types.h, rt_atm.c, rt_solver.c, main.c). diff가 어긋나는 파일은 이 전문과 대상 파일을 대조해 수동 이식한다.
3. `docs/`: 본 가이드와 구현 상세 문서.
4. `verify/verify_pssa_port.sh`: 이식 후 검증 스크립트.
5. `data/pssa_vs_paper_fig11_12_comparison_v2_2026-07-18.csv`: 논문 대비 검증 근거 표(기대값의 출처).

## 1. 이식 원칙
1. 최우선 불변조건: `--pssa`를 켜지 않으면 대상 코드의 기존 결과와 비트 단위로 동일해야 한다. 사이트 하나를 이식할 때마다 off 경로 A/B 비트 비교를 수행한다. 마지막에 몰아서 확인하지 않는다.
2. 모든 소비 지점은 `atm->pssa_active` 플래그로 분기한다. off 분기의 식은 대상 코드의 원식을 문자 그대로 유지한다(부동소수점 연산 순서가 바뀌면 비트가 깨진다).
3. 신규 파일 rt_pssa.h/rt_pssa.c는 자가완결이다. 의존성은 rt_types.h의 rt_atm_t 필드(h, z_km_level, ch, mu_sun, n_layers)와 아래 3절의 추가 필드뿐이다.
4. 전 지점에 "PSSA 2026-07-18" 태그 주석을 유지한다. 이식 후 `grep -rn "PSSA 2026-07-18" src/`로 전수 확인이 가능해야 한다.

## 2. 적용 순서 (단계마다 빌드 + off 비트 A/B)
1. 1단계 — 타입: rt_types.h에 rt_atm_t 필드 4개(pssa_active, pssa_xi_dn, pssa_xi_refl, pssa_alpha)와 rt_options_t의 `int pssa`(기본 0)를 추가한다. rt_atm.c의 alloc에 0/NULL 초기화, free에 NULL 안전 해제를 추가한다. 컴파일만 확인.
2. 2단계 — 신규 파일: rt_pssa.h와 rt_pssa.c를 그대로 복사한다. 대상 코드의 rt_atm_t 멤버명이 다르면(h, z_km_level, ch, mu_sun, n_layers) rt_pssa.c 안에서만 이름을 맞춘다.
3. 3단계 — 훅: 대기 흡수 적용으로 h[]가 최종화된 직후 지점을 찾아 `if (opts->pssa) { if (rt_pssa_apply(&atm) != 0) { rc = -1; goto cleanup; } }`를 넣는다. #include "rt_pssa.h"도 추가.
4. 4단계 — 사이트 B(반사빔 소스): FSOURCE_DIFF_FRESNEL1 블록. kl 루프 밖에서 c_ref/F11/F12 배열을 사전계산하고, 루프 안에서 COEFK *= c_ref[kl], COEFKP1 *= c_ref[kl+1], F11/F12를 레벨별 값으로 교체한다. 블록 끝에서 해제.
5. 5단계 — 사이트 C·C': trans_sun_to_surf의 하향 레그 교체 두 곳.
6. 6단계 — 사이트 D: rho_glint 재척도 세 곳(단일 뷰, 진단, 격자 — 격자는 상수 호이스트).
7. 7단계 — 사이트 E: out->T_dir_dn 삼항 분기.
8. 8단계 — 사이트 F·H: 해양 드라이버 헬퍼 ocrt_pssa_T_dir_dn_for_ocean() 이식 후 F_sun_BOA와 out->T_dir_dn 연결.
9. 9단계 — CLI: main.c 파싱과 도움말.
10. 10단계 — 전체 검증(4절 프로토콜).

## 3. 사이트별 앵커와 주의점
대상 코드가 v1.1에서 리팩터링되어 줄 번호와 이름이 바뀌었을 수 있으므로, 문자열 앵커가 실패하면 아래 "개념 앵커"로 지점을 찾는다.

| 사이트 | 문자열 앵커(v1.1) | 개념 앵커 | 주의점 |
|---|---|---|---|
| 훅 | rt_solver.c:601 부근, 흡수 적용 호출 직후 | h[]가 레일리+에어로솔+기체흡수 전부 반영된 "직후" | 흡수 이전 호출 금지. 실패 시 cleanup 경로 준수 |
| B | `FSOURCE_DIFF_FRESNEL1` | 평면 해수면 반사 직달빔의 1차 소스 항(레벨 kl, kl+1 계수) | c_ref는 "구면÷평면" 비율이라 대상의 평면 공식이 다르면 지수 항을 그 공식에 맞춰 재구성. COEFKP1 부호 구조 보존. 배열은 루프 밖 사전계산 |
| C | `trans_sun_to_surf` (Cox-Munk 1차 반사) | 태양→표면 직달 감쇠에 exp(−τ/μs)를 쓰는 곳 | 하향 레그만 교체. 상향 exp(−Δτ/μ)는 평면 유지 |
| C' | 같은 변수, RII 디버그 경로 | 진단 전용 동일 물리 | 동일 |
| D | `rho_glint` 세 곳 | 직달 선글린트에 왕복 감쇠를 곱하는 곳 | 하향 레그만 재척도: ×exp(−(ξ_dn[nt] − τ/μ0)). 격자 경로는 루프 밖 상수로 |
| E | `out->T_dir_dn` | 직달 하향 투과 출력 | off 분기 원식 문자 그대로 |
| F | `ocrt_T_dir_beam`, `F_sun_BOA` | 해양 결합에서 표면 도달 태양 직달 인자 | 헬퍼는 실제 대기 빌더+흡수로 일회용 atm 구성(n_mu=1). τ_R+τ_a≤0 또는 에어로솔 배열 부재 시 평면 폴백 |
| H | `out->T_dir_dn` (해양 경로) | F의 공유 변수 재사용 | F~H 사이에서 tau_atm/mu_sun_air 재대입이 없는지 대상 코드에서 반드시 재확인 |

추가 주의 세 가지다.
1. ch[k]의 의미가 대상 코드에서 0.5·exp(−h/μs)인지 확인한다. 계수(0.5)나 정의가 다르면 rt_pssa_apply의 덮어쓰기 식을 그 정의에 맞춘다.
2. 수중 계산이 별도 atm을 할당하는 구조인지 확인한다. 할당부 0 초기화 덕에 pssa 상태가 수중으로 전파되지 않는 설계다. 대상 코드가 atm을 재사용한다면 수중 진입 전에 pssa_active를 끄는 안전장치가 필요하다.
3. Δz=0 층(같은 고도의 연속 레벨)이 있어도 상쇄 없는 시컨트 공식은 유한하다. 층 시컨트를 (F_i − F_{i+1})/Δz 꼴로 "최적화"하지 않는다.

## 4. 검증 프로토콜 (이식 완료 판정 조건)
1. off 비트 A/B. 대상 코드의 이식 전 바이너리를 보존해 두고, 아래 9개 대표 명령(또는 대상 코드에서 유효한 등가 명령)에서 stdout 비트 동일을 확인한다: 검은 표면(sza 30/75), 평면 프레넬(sza 60/85), Cox-Munk 풍속 5(글린트 포함/decouple), M80C 에어로솔, 해양(τ=0, 443 대기 포함). `verify_pssa_port.sh`가 자동화한다.
2. 자체 앵커. 대상 코드의 기준 결과(Tier-0급 앵커)가 있으면 그것을 재현한다. v1.1 기준값은 rrs0minus=2.887685e-02이나, 수정본의 앵커는 수정본의 것을 따른다.
3. pssa 스모크(같은 물리라면 재현되어야 하는 값, 표준 대기·기체흡수 0·평면 프레넬·나디르·n_layers=400 기준):
   - 412 nm: (SA−PP)/PP = 0.3953 / 0.9682 / 2.8905 / 12.5076 % (sza 70/75/80/85)
   - 443 nm: 0.2929 / 0.7749 / 2.5399 / 12.1549 %
   - 파장비(443/412): 0.741 / 0.800 / 0.879 / 0.972
   허용 오차는 상대 0.5%다(기계·컴파일러에 따른 마지막 자리 차이 허용). 수정본이 레일리 τ 모델이나 연직 프로파일을 바꿨다면 이 값은 그만큼 이동하므로, 이동 원인을 명시하고 새 기대값을 기록한다.
4. n_layers 민감도 방향 확인. n_layers 40이 400보다 크게 나와야 한다(85도에서 약 +10% 상대). 부호가 반대면 층 격자 해석이 잘못된 것이다.
5. 해양 스모크. 443 nm, sza 75, 풍속 3에서 rho_I가 +0.9% 부근으로 증가하고 Rrs는 0.05% 이내로 불변이어야 한다(상쇄 구조).
6. 검증 범위 준수. 스모크·비교 모두 태양천정각 85도 이하에서만 수행한다.

## 5. 실패 시 진단 순서
1. off 비트가 깨졌다: 분기 밖으로 코드가 샜다. 해당 단계의 diff를 다시 보고 off 분기 원식의 문자 동일성을 확인한다.
2. pssa 값이 수 % 이상 어긋난다: (a) 훅 위치가 흡수 이전인지, (b) ch 정의·0.5 계수, (c) c_ref 지수의 평면 항이 대상 공식과 일치하는지, (d) F~H 사이 변수 재대입 순으로 본다.
3. 85도에서만 크게 어긋난다: 상쇄 없는 F식 대신 직접 뺄셈 형태를 썼는지 확인한다.
4. 해양만 어긋난다: 헬퍼의 일회용 atm이 실제 빌더·흡수를 그대로 쓰는지, 폴백 조건이 대상 코드의 대기 구성과 맞는지 확인한다.
